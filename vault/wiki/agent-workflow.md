# Agent workflow

How agents (main and sub) work on this repo. The live rules are in the repo-root `AGENTS.md`; `CLAUDE.md` only contains `@AGENTS.md`, so edit AGENTS.md, not CLAUDE.md. The workflow section sits after the `nextjs-agent-rules` block so that managed block is not overwritten. (see [[2026-11-27-agent-workflow]])

## Rules
1. All coding work uses the `ponytail` skill; subagent briefs must say so.
2. Read before write: the matching `node_modules/next/dist/docs/` guide and the files to touch.
3. Verify before claiming done: `npx eslint src scripts` (see [[code-quality]] for why not repo-wide lint), `npm run build`, tests, preview browser for UI.
4. Never commit, push or publish unless the owner asks.

## Pipeline
Understand -> Plan -> Implement -> Verify -> Review -> Report. Main agent verifies and reports; subagents implement.

## Model routing
| Tier | Examples | Who |
|---|---|---|
| Trivial | typo, one-line tweak | main agent |
| Simple | single-file edit, bulk replace, small docs | Haiku 5.5 |
| Standard | multi-file feature, bug fix, refactor, tests | Sonnet 5.5 |
| Hard | architecture, unclear bug, security | main agent, then mandatory review |

Escalate when unsure; a Haiku result failing verification once moves to Sonnet. Parallel only on different files. Review (`ponytail-review`, `code-review`) required from medium tasks up.

## The "NOT the Next.js you know" block
The block at the top of `AGENTS.md` (between `<!-- BEGIN:nextjs-agent-rules -->` and `<!-- END:nextjs-agent-rules -->`) was generated by `create-next-app` in the first commit. It is a warning to agents, not an error: the site runs Next.js 16.2.1, newer than most models' training data, and Next.js bundles version-matched docs in `node_modules/next/dist/docs/`. Rule 2 above depends on it. Owner decision 2026-11-27: keep it unchanged. If it is ever reworded, keep the BEGIN/END markers so Next.js tooling can still find the block. (see [[2026-11-27-agents-md-nextjs-warning]])

## Industry practice (reference)
Understand, plan, small steps, verify with real feedback, separate review, PR for a human to merge. Plus orchestrator and cheaper workers, fresh context per subagent, worktree isolation, tight permissions, CI guardrails, rules in files, evals.
